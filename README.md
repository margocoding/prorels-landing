Добавлен блог: карточки на главной, список `/blog` и отдельные страницы статей с SEO. Наполнение, публикация статей и параметры Docker-сборки описаны в [BLOG.md](./BLOG.md).

## Запуск

Нужен Node.js 22.18+ (проверено на 24.14).

```sh
npm ci
npm run dev
```

Адрес разработки: http://127.0.0.1:4193.

Готовая сборка с самостоятельным сервером:

```sh
npm run build
npm start
```

`build` копирует изображения, шрифты и статические файлы в `.next/standalone`. Для переноса на сервер достаточно содержимого `.next/standalone`; запускать из этой папки `node server.js` с `PORT=3000` и нужным `HOSTNAME`. Локальный `npm start` использует `127.0.0.1:4193`; порт меняется через `PORT`, интерфейс через `LISTEN_HOST`. Не открывайте локальную тестовую сборку наружу вместо отдельного размещения.

## Домен и SEO перед публикацией

Публичный домен — https://prorels.com. Локальная сборка без параметров остаётся закрытой от индексации: `noindex, nofollow` в HTML и `X-Robots-Tag`, без canonical и без URL в sitemap. Robots разрешает обход, чтобы поисковик мог прочитать noindex.

1. Скопировать `.env.example` в `.env.local`.
2. В `SITE_URL` указать HTTPS-адрес **лендинга**, без пути. Не использовать адрес основного каталога.
3. Установить `SITE_INDEXABLE=true` только для публичной версии.
4. При необходимости добавить коды подтверждения Google и Яндекс в предусмотренные переменные.
5. Выполнить `npm run build` заново и перезапустить сервер. Метаданные и sitemap формируются при сборке.
6. Настроить DNS, HTTPS и обратный прокси выбранного домена; проверить итоговые адреса перед отправкой sitemap в панели вебмастеров.

Конфигурация не позволяет включить индексацию без домена, использовать HTTP, URL с путём/параметрами или канонизировать лендинг на prorelsa.ru / traer.ru. Для Vercel preview индексация дополнительно отключается по `VERCEL_ENV=preview`.

Workflow `Deploy` перед сборкой образа выполняет проверки приложения, включая настоящую отправку в локальный SMTP-приёмник. Если они падают, публикация образа и деплой не запускаются. Production-сборка по умолчанию использует `SITE_URL=https://prorels.com` и `SITE_INDEXABLE=true`; переменные репозитория с этими именами могут переопределить значения. SMTP передаётся отдельно при запуске контейнера, см. [MAIL.md](./MAIL.md).

В production от одного `SITE_URL` формируются canonical, Open Graph URL, адрес картинки для соцсетей, WebSite JSON-LD и sitemap. Organization связан с основным сайтом компании. У несуществующих страниц — настоящий статус 404 и noindex, без canonical на главную. Автоматические текущие даты в sitemap не подставляются.

Реализовано: статическая генерация полного HTML, `lang=ru`, один H1 и последовательные заголовки, title/description, robots, sitemap, Organization/WebSite JSON-LD, favicon, OG/Twitter-карточка 1200×630, локальные кириллические шрифты, адаптивные изображения AVIF/WebP и загрузка главной фотографии с приоритетом. Форма отправляет почту, телефон, комментарий, страницу обращения и доступные UTM-метки через API Next.js. Ссылка на политику ведёт на основной сайт. Cookies и счётчики не подключены.

## Проверка

```sh
npm run lint
npm run typecheck
npm test
npm run build
npm run verify:contact
npm start
# В другом терминале:
npm run verify:seo
```

`verify:seo` проверяет полученный HTML, внешние ссылки категорий, JSON-LD, robots/sitemap, PNG-превью и реальный 404. По умолчанию ожидается тестовый noindex.

Для проверки публичной сборки указать `VERIFY_SITE_ORIGIN` равным `SITE_URL` и `VERIFY_INDEXABLE=true`; для другого локального порта — `VERIFY_URL`. Эти переменные задают ожидаемые значения теста, а не меняют приложение.

Результаты и границы проверки — в `VERIFICATION.md`. Автоматические проверки используют локальный SMTP-приёмник. Реальное подключение к Timeweb проверено отдельно; получение письма в рабочем ящике требует отдельной проверки после обновления сервера.
